## 3. How every phase is built and released

This process applies to every phase below.

1. **Plan.** Write or update the spec section; list files, migrations, open questions. Agree it with the owner before code.
2. **Build on the development database.** `koko_finance_dev` (refresh with `scripts/finance-copy-live.js` when real data is needed). Never post journals or create test records on live.
3. **Test.** Add `node:test` tests for every rule (run-stamped names, far-future fiscal years); `npm run test:finance` and `npm run build` must pass.
4. **Click through.** Puppeteer walkthrough of the new screens at desktop and 390 px; no page errors.
5. **Release to live.**
   1. Fingerprint the live business data over a fixed column list.
   2. `node scripts/migrate.js --status`, then `node scripts/migrate.js`.
   3. Fingerprint again and compare; explain any difference.
   4. Push to `master` (Vercel deploys).
   5. Run any backfill and confirm a second run changes nothing.
6. **Record.** Update the spec, these documents if behaviour changed, and the release notes in commit messages.

**Definition of done:** feature works for each role that should see it (and is hidden from those that shouldn't), mobile layout checked, errors are actionable, audit entries written, tests and build green, live data verified unchanged except as intended.

## 6. Risks and mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Testing on live data | Wrong records in the real system | Development database for anything that writes test data; fingerprints around migrations; non-GET requests blocked in live UI checks |
| One person holds the business rules | Slow decisions, knowledge loss | These documents, in-app help, spec decisions recorded in Section 0 of the finance spec |
| Vercel 60 s function limit | Long jobs fail | Batch jobs driven by the browser; scripts for backfills |
| Files in the database grow storage | Cost, slower backups | 2.5 MB limit; move to Drive in F4–F6 |
| Single reseller assumptions | Bugs when a second reseller joins | Test a second reseller on the development database before onboarding |
| Estimated historic dates | Revenue in the wrong month | Flags on orders; review before year end |
