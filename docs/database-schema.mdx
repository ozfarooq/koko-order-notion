# Koko Atelier CRM: Database Schema (Backend)

| Item | Detail |
| --- | --- |
| Engine | Neon Postgres 16 (serverless). Live database `neondb`; development and test database `koko_finance_dev` (same structure) |
| Baseline | `db/schema.sql` |
| Migrations | `db/migrations/002…018`, applied by `scripts/migrate.js`, recorded in `schema_migrations` |
| Snapshot | Structure and row counts read from the live database on 23 November 2026 |
| Related | [TRD](./technical-requirements.mdx) · [Finance module spec](./finance-module.mdx) |

## 1. Conventions

| Convention | Rule |
| --- | --- |
| Names | snake_case tables and columns; plural table names; finance tables prefixed `fin_` |
| Keys | `SERIAL` / `BIGSERIAL` integer ids; UUIDs (`gen_random_uuid()`) for orders, customers, consignment items and stock pieces |
| Money | `NUMERIC(12,2)` (CRM) / `NUMERIC(14,2)` (finance); never floats. Retail in PKR (`_pkr` suffix); reseller prices in the reseller's currency |
| Dates | `DATE` for business dates (Pakistan date); `TIMESTAMPTZ` for events (`created_at`, `at`) |
| Audit columns | `created_at`, `updated_at` (kept current by `*_touch` triggers), `created_by` / `updated_by` → `users.id` |
| Enumerations | `TEXT` with `CHECK (… IN (…))` constraints, listed in Section 4 |
| Rules | Money rules that must never break live in the database (checks, generated columns, triggers), not only in code |

## 2. Domain map

```
                 users ─── sessions          audit_log (every write)
                   │
        ┌──────────┴───────────┐
   customers ──< orders ──< order_items >── products >── collections
                   │  └──< customer_payments              │
                   │  └──< stock_pieces >───────────────────┤
                   │          └──< stock_movements           │
   resellers ──< consignments ──< consignment_items >───────┘
       │   └──< reseller_products (design codes)       │
       └──< reseller_payments ──< reseller_payment_files│ (payment_id)
                                                        │
 FINANCE  fin_settings · fin_accounts · fin_periods · fin_sequences · fin_fx_rates
          fin_entries ──< fin_lines (→ orders, products, collections, consignment_items)
          fin_files ── fin_file_blobs ; fin_entry_files
          fin_suppliers · fin_staff ──< fin_staff_salary
          fin_expenses (+files) · fin_recurring · fin_claims ──< fin_claim_lines (+files)
          fin_payroll_runs ──< fin_payroll_lines ──< fin_payroll_hours ; fin_payroll_income (+files)
          fin_staff_payments ──< fin_staff_payment_parts (+files)
          fin_intake_items · fin_intake_labels · fin_post_exceptions
```

`──<` one-to-many · `>──` many-to-one.

## 6. Triggers and database rules

| Table | Trigger / rule | What it does |
| --- | --- | --- |
| customers, orders, consignment_items, stock_pieces, users | `*_touch` (before update) | Keeps `updated_at` current |
| orders | `balance_due_pkr` (generated) | amount − advance; 0 when Cancelled / Returned |
| orders | `orders_pr_free_chk` (check) | PR orders always free |
| orders | `orders_status_dates` (before insert/update) | Sets `status_changed_on`; sets `paid_on` when the order becomes Paid |
| orders | `orders_advance_to_payment` (after insert/update of advance) | Any change to the advance made outside the payments table becomes a payment row |
| customer_payments | `customer_payments_sync` (after insert/update/delete) | `orders.advance_paid_pkr` = sum of payments |
| stock_pieces | `stock_pieces_log` (after insert/update) | Writes `stock_movements` |
| fin_entries | `fin_entries_guard` (before insert/update) | Numbering on post; posted entries immutable except Posted → Reversed; period must be Open (owner may post into Closed with a reason via `set_config('koko.role')`); Locked refuses |
| fin_entries | `fin_entries_balanced` (deferred constraint trigger) | Debits = credits for every posted entry at commit |
| fin_entries | `fin_entries_no_delete` | Only drafts can be deleted |
| fin_lines | `fin_lines_guard` | Lines of posted entries cannot change; control accounts blocked in manual journals |
| fin_accounts | `fin_accounts_guard` | An account with postings cannot be deleted (make it inactive) and its code and type cannot change |
| fin_entries | unique index on (source_type, source_id, source_event) where not Reversed | The same business event never posts twice |

## 8. Working with the database

- Add a table or column only through a new migration file, and add one line to the `db/schema.sql` header.
- Run migrations with `node scripts/migrate.js` after fingerprinting live data; check `--status` first.
- Rehearse risky migrations on `koko_finance_dev` after copying live data (`node scripts/finance-copy-live.js`).
- Never run tests or scripts that post journals against `neondb`.
- Indexes worth knowing: `orders(status)`, `orders(customer_id)`, `customers(lower(name))`, `customers(phone)`, `consignment_items(status)`, `fin_lines(order_id)`, `fin_lines(collection_id)`, `customer_payments(order_id)`, `fin_intake_items(status, created_at)`.
